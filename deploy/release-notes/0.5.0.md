## Every network has to be founded again

This version changes the roster's format, and a network made by 0.4 can't be carried over. On every
device:

1. **Install** this version, over the old one.
2. **Found** the network again on the device that was its admin:
   `peerfectly found home --relay https://relay.example --name laptop`.
3. **Invite** each other device back: `peerfectly invite nas` on the admin, `peerfectly join <the
   invite>` on the device, then `peerfectly pending` and `peerfectly approve nas` on the admin.

A device still holding a 0.4 network reports it as one it can't carry. `peerfectly forget <network>`
(as administrator) clears it away.

## What's new

- **Joining no longer needs both people at once.** An invite stays open for a day by default
  (`--expires 30m|24h|7d`). The joining device sends its request and returns. The admin's daemon
  collects the request on its own, and the admin approves it when they choose. Either machine may be
  off or restart in between. The device is given the network by the admin or, when the admin is off
  by then, by a member near it.
- **One list of what waits:** `peerfectly pending` shows open invites, requests to approve or
  reject, this device's own joins, and acts waiting on a person. The Android app has the same page,
  and notifies when a request arrives and when the phone is admitted.
- **A fingerprint instead of a six-digit code.** The joining device shows its key's fingerprint, and
  the request shows the same one: compare them if you're both there. The code is gone: sent remotely
  it was a second secret anyone holding the invite could read, and it could be forced in seconds.
- **One rule for who may do what.** Without an administrator (an elevated console on Windows,
  `sudo` on Linux) you can read (`status`, `peers`, `address`, `exposed`, `pending`) and turn your
  own networks on and off; everything else asks for one, and the command line says so before it
  starts. On the phone, the same acts ask for the phone's lock.
- **Large networks.** The state is a Merkle tree, a signed root follows every admin act, and devices
  keep a window instead of the whole history.
  - **Light members**, such as a phone that shouldn't carry a large network or a small board, hold
    only their own proof and the latest root.
  - **A batch** admits thousands of devices with one consent: `peerfectly admit --batch <file>`.
  - **Anchors**, full members an admin names with `peerfectly set-anchors`, keep light members in
    touch.
- **No expiry by default.** A network no longer stops trusting a roster after a week without news;
  a cut-off island keeps working. A network can still set a freshness window when it is founded.
- **Files changed behind the daemon are not believed.** This covers invites, requests, a join in
  progress and a light member's state, whether the daemon is running or stopped.

## Removed

- `admit <payload>` and the joining payload: a device joins from an invite.
- The six-digit code and `peerfectly resume`.
- The notification-area item that announced an arriving device. Windows shows nothing of enrolment
  in the tray; `peerfectly pending` does.
